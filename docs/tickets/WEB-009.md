# WEB-009 — MARC Pulse home experience

Status: NOT_STARTED

## Goal

Offer a useful line overview within the existing contract.

## Why

This delivers the next bounded part of the local commuter milestone while preserving the data-trust and minimal-design rules.

## Dependencies

[WEB-005](WEB-005.md), [WEB-008](WEB-008.md)

## Scope

Create three line sections linking to filtered trains plus a small MARC advisory preview. Summarize reported official statuses only with clear service-date scope and completeness/unknown coverage; prefer plain explanatory text when counts would mislead.

## Out of Scope

Active/stationary counts, fabricated healthy line status, N+1 movement reads and backend aggregation.

## Expected Files

app/page.tsx, Pulse presentation components/helpers, home tests.

## Implementation Notes

Whole-day list is not running-now evidence. Never call a line Normal service because delays are absent. Partial pages cannot produce total counts. Keep the overview useful with line links and clear unavailable coverage rather than inventing confidence.

## Acceptance Criteria

Home answers what is known and what is unavailable; line links preserve date; advisories remain contextual; no KPI-card wall or unsupported operational totals.

## Tests Required

Test unknown-only and partially paginated data, reported delays, unavailable alerts, line links and provenance. Verify request count is bounded and no detail fan-out; run all checks.

## Manual Verification

Inspect real retained data and synthetic mixed/empty/error cases at both widths. Verify the leading message is understandable within five seconds.

## Design Verification

Inspect rendered mobile and desktop views using [the design checklist](../DESIGN.md). Review hierarchy, spacing, wrapping, color-independent status and applicable loading/empty/error/real-data states. Capture screenshots when possible; record evidence and inapplicable states. Automated tests alone do not satisfy this gate.

## Definition of Done

All acceptance criteria and required checks actually pass; rendered verification is complete where applicable. Review the diff, record exact results and any limitations here, and update the ticket index, CURRENT_STATE.md and relevant runbook/design/contract docs. One completed-ticket commit with a WEB-009 subject; preserve unrelated work. If blocked, document why and leave IN_PROGRESS rather than making a completion commit.
