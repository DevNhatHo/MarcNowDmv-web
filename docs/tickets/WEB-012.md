## Outcome

Added `tests/e2e/integration.spec.ts`, the **only** suite that needs the Go backend running.
Everything else in the repository stays deterministic, so CI never depends on a live
service. It asserts behaviour rather than any particular train, time or count, so it keeps
working as the retained data changes.

It exercises the whole path — browser to same-origin proxy to backend — across all four
screens: proxy health and allowlist, the contract's own 400 and 404 responses reaching the
screen as copy, the Pulse → filtered list → detail → back journey with filters restored
exactly, chronological ordering, pagination that completes and says so, provenance
separation on detail, safe links on alerts, an explicit refresh, and every screen with the
backend unreachable.

Checks actually executed: `npm test` (**11 files, 169 tests**), `npm run lint` (zero
warnings), `npm run typecheck`, `npm run build` and `npx playwright test` (**46 tests, 23
per viewport**, covering shell, accessibility and integration).

Live results are tabulated in [the smoke record](../reviews/WEB-012/README.md). The ones
worth naming here: non-contract paths return 404 **without the backend being contacted**;
`POST` returns 405; the journey restored `?serviceDate=20260930&routeId=11704` exactly; and
with the backend unreachable every screen reads "Couldn't reach the service" while **neither
"On time" nor "No active MARC alerts reported" appears anywhere** — an outage never reads as
good news.

One integration defect was found and fixed: the detail error page showed **two identical
"Back to trains" links**, one above the notice and one inside its actions. The notice now
offers only the action it adds.

One contract discrepancy was re-confirmed live at the HTTP level: on the same real
identifier, the documented `?stopAfter=1` returns **400** while the implemented
`?afterStop=1` returns **200**. That is BACKEND-UI-04; the backend was not modified.

## Limitations

The retained database holds no fresh realtime evidence, so the live journey shows every
train as "Realtime status unavailable" and every calculation as unknown. The delayed,
cancelled, moving, stationary and trend presentations rest on unit tests and clearly
labelled synthetic fixtures, not on this smoke test. Chrome only; no screen reader, no
second engine, no load or soak testing.

No blockers. The core local milestone (WEB-001 through WEB-012) is complete. The map
follow-on WEB-MAP-1 is now unblocked; WEB-MAP-2 and WEB-MAP-3 remain gated on the
BACKEND-UI-03 and BACKEND-UI-02 proposals, which have not been delivered.
