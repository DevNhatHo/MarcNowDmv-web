# WEB-002 — Establish minimal design tokens and visual foundation

Status: NOT_STARTED

## Goal

Create the restrained visual vocabulary used by all screens.

## Why

This delivers the next bounded part of the local commuter milestone while preserving the data-trust and minimal-design rules.

## Dependencies

[WEB-001](WEB-001.md)

## Scope

Implement CSS custom properties for the small spacing/type/neutral/semantic/border/radius system; system font, focus states, responsive width and reduced-motion defaults. Demonstrate token use on the starter page.

## Out of Scope

Full component library, dark theme, remote fonts, product data and complete shell.

## Expected Files

app/globals.css, app/page.tsx, local CSS Modules as needed, docs/DESIGN.md.

## Implementation Notes

Use DESIGN.md as a starting proposal, then adjust based on rendered contrast and wrapping. Color never carries a status alone. Keep body text readable and controls touch-friendly.

## Acceptance Criteria

Tokens are consistently used; actual text/focus contrast is checked; 360px content has no horizontal overflow; keyboard focus and reduced motion work.

## Tests Required

Run established test/lint/typecheck/build checks; avoid snapshot tests that merely mirror CSS. Record contrast measurements and keyboard observations.

## Manual Verification

Inspect mobile/desktop typography, long identifiers, grayscale status labels, focus and 200% zoom. Data lifecycle states are not yet applicable.

## Design Verification

Inspect rendered mobile and desktop views using [the design checklist](../DESIGN.md). Review hierarchy, spacing, wrapping, color-independent status and applicable loading/empty/error/real-data states. Capture screenshots when possible; record evidence and inapplicable states. Automated tests alone do not satisfy this gate.

## Definition of Done

All acceptance criteria and required checks actually pass; rendered verification is complete where applicable. Review the diff, record exact results and any limitations here, and update the ticket index, CURRENT_STATE.md and relevant runbook/design/contract docs. One completed-ticket commit with a WEB-002 subject; preserve unrelated work. If blocked, document why and leave IN_PROGRESS rather than making a completion commit.
