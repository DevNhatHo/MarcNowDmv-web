# WEB-010 — Central polling and resilient freshness states

Status: DONE (2026-09-30)

## Goal

Keep screens current without noisy refreshes or false live claims.

## Why

This delivers the next bounded part of the local commuter milestone while preserving the data-trust and minimal-design rules.

## Dependencies

[WEB-007](WEB-007.md), [WEB-008](WEB-008.md), [WEB-009](WEB-009.md)

## Scope

Add one shared resource lifecycle with centralized intervals, deduplication, abort/supersession, hidden-tab pause, focus refresh, bounded backoff and retry. Preserve last successful content while marking failures or aged response caches outdated.

## Out of Scope

WebSockets, backend freshness algorithms, client movement computation and speculative prefetch fan-out.

## Expected Files

lib/refresh/*, resource hooks, refresh indicators, fake-clock and browser tests, docs/RUNBOOK.md.

## Implementation Notes

Use architecture intervals: trains/detail 30s, alerts 60s, catalogs 10min/version. No overlapping fetches. Failure immediately marks last-received content; two missed intervals mark response cache outdated. Backend evidence freshness remains separate.

## Acceptance Criteria

No per-second polling or unbounded cursor traversal; stale cached positive labels are historical; route changes cannot show old response data; retry is available; background refresh preserves layout and focus.

## Tests Required

Fake-clock tests for intervals/backoff, single ownership, hidden/resume, cancellation, out-of-order completions, unmount, errors/recovery and aged cache. Browser-check quiet refresh; execute all checks.

## Implementation decisions

**One entry per resource key, however many components subscribe.** Deduplication falls out
of that: two screens showing the same catalog share one request and one timer rather than
racing. `lib/refresh/store.ts` owns the lifecycle and `useSharedResource` is the only way
screens touch it, through `useSyncExternalStore`.

**A failed refresh keeps the last successful content.** Failure changes how content is
labelled, never whether it is there. Removing it would lose information the commuter already
had; showing it unchanged would imply it is current, so it is framed as last received.

**Polling pauses entirely while the document is hidden**, but the timer keeps ticking and
still notifies. That is what lets an age label and the outdated wording stay truthful with no
network call, which the architecture asks for explicitly.

**`outdated` is about this app's response cache, not the backend's freshness.** Two missed
intervals, or any failure, means the cached positive claims stop being presented as current.
The backend's own `freshness` and `sourceHealth` remain the authority on the evidence, and
nothing here recomputes them.

**Pagination is never automated.** A timer re-reads the first page and never follows a
cursor; loading more stays an explicit action, which a test pins.

## Outcome

Added `lib/refresh/policy.ts` and `lib/refresh/store.ts`, `components/useSharedResource.ts`
and a shared `components/Freshness.tsx` banner, and migrated all four screens onto them. The
per-screen "Received …" lines and refresh buttons are gone, so that wording now exists once.
`useResource` from WEB-005 is superseded and removed.

Checks actually executed: `npm test` (**11 files, 169 tests**, 0 failures), `npm run lint`
(zero warnings), `npm run typecheck`, `npm run build` and `npx playwright test`.

Fourteen fake-clock tests cover per-resource cadence, subscriber deduplication,
unsubscribe-keeps-cache, hidden-tab pause with zero requests across four intervals, paused
notification without a request, visibility wake, content retention on failure, backoff
doubling to the 120 s ceiling, failure-count reset, superseded-response discard, in-flight
abort, and the rule that a tick never follows a cursor.

Rendered verification against the live backend recorded **two requests in a 33-second
window** — one poll cycle, no cursor followed — and, with the backend aborting, **all fifty
rows still on screen** under "Couldn't refresh. Showing information received just now."
0 px overflow and no page errors at both viewports.

One structural change was needed in the test suite: the store is shared across the whole app
by design, so `tests/setup.ts` now resets it after every test, and the three tests that
render the same key twice reset it between scenarios. Without that they would render a
previous scenario's cached response — which is correct product behaviour and a real trap.

## Limitations

The 120-second backoff ceiling, the two-missed-interval outdated threshold and the
ten-minute catalog cadence are exercised by the fake-clock suite, **not** by a screenshot;
reproducing them live would mean sitting on a broken backend for minutes. The captured
failure shows the immediate case. Chrome only; not a full accessibility audit.
