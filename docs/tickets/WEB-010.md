# WEB-010 — Central polling and resilient freshness states

Status: NOT_STARTED

## Goal

Keep screens current without noisy refreshes or false live claims.

## Why

This delivers the next bounded part of the local commuter milestone while preserving the data-trust and minimal-design rules.

## Dependencies

[WEB-007](WEB-007.md), [WEB-008](WEB-008.md), [WEB-009](WEB-009.md)

## Scope

Add one shared resource lifecycle with centralized intervals, deduplication, abort/supersession, hidden-tab pause, focus refresh, bounded backoff and retry. Preserve last successful content while marking failures or aged response caches outdated.

## Out of Scope

WebSockets, backend freshness algorithms, client movement computation and speculative prefetch fan-out.

## Expected Files

lib/refresh/*, resource hooks, refresh indicators, fake-clock and browser tests, docs/RUNBOOK.md.

## Implementation Notes

Use architecture intervals: trains/detail 30s, alerts 60s, catalogs 10min/version. No overlapping fetches. Failure immediately marks last-received content; two missed intervals mark response cache outdated. Backend evidence freshness remains separate.

## Acceptance Criteria

No per-second polling or unbounded cursor traversal; stale cached positive labels are historical; route changes cannot show old response data; retry is available; background refresh preserves layout and focus.

## Tests Required

Fake-clock tests for intervals/backoff, single ownership, hidden/resume, cancellation, out-of-order completions, unmount, errors/recovery and aged cache. Browser-check quiet refresh; execute all checks.

## Manual Verification

Observe browser Network over multiple intervals, hide/resume tab and stop/restart backend. Inspect retained content and error/recovery on mobile/desktop without spinner replacement.

## Design Verification

Inspect rendered mobile and desktop views using [the design checklist](../DESIGN.md). Review hierarchy, spacing, wrapping, color-independent status and applicable loading/empty/error/real-data states. Capture screenshots when possible; record evidence and inapplicable states. Automated tests alone do not satisfy this gate.
