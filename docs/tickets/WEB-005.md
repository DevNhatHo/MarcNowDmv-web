# WEB-005 — Service-date train list

Status: NOT_STARTED

## Goal

Help commuters choose a train without inventing active-service semantics.

## Why

This delivers the next bounded part of the local commuter milestone while preserving the data-trust and minimal-design rules.

## Dependencies

[WEB-003](WEB-003.md), [WEB-004](WEB-004.md)

## Scope

Fetch bounded train pages and matching route catalog; add line/service-date URL filters, scheduled time, official status, timestamps, detail links, explicit refresh and load-more. Implement loading/error/empty/stale evidence states.

## Out of Scope

Movement/trend rows, active or stationary totals, N+1 detail calls and automatic polling.

## Expected Files

app/trains/page.tsx, components/TrainRow*, lib/presentation/status.ts, lib/presentation/time.ts, train-list tests.

## Implementation Notes

List is a service-day schedule including completed trains. Use verbatim tripId fallback; no invented train numbers/headsigns. Default date respects feed timezone, retain YYYYMMDD on API boundary, and avoid mixed-version catalog joins.

## Acceptance Criteria

Filters survive navigation; partial pages are identified; UNKNOWN/stale official data never reads On time; zero versus null delay differs; empty copy says no scheduled trains for selected date/filter.

## Tests Required

Test filtering/query encoding, pagination/version reset, unknown status, stale retained ON_TIME, null delay, errors, empty results and superseded-request cancellation. Run all established checks.

## Manual Verification

Browse real local schedule rows, change dates/lines, load another page and open detail. Review synthetic error/empty states at both widths.

## Design Verification

Inspect rendered mobile and desktop views using [the design checklist](../DESIGN.md). Review hierarchy, spacing, wrapping, color-independent status and applicable loading/empty/error/real-data states. Capture screenshots when possible; record evidence and inapplicable states. Automated tests alone do not satisfy this gate.

## Definition of Done

All acceptance criteria and required checks actually pass; rendered verification is complete where applicable. Review the diff, record exact results and any limitations here, and update the ticket index, CURRENT_STATE.md and relevant runbook/design/contract docs. One completed-ticket commit with a WEB-005 subject; preserve unrelated work. If blocked, document why and leave IN_PROGRESS rather than making a completion commit.
