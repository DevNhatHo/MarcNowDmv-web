# WEB-008 — MARC alerts experience

Status: NOT_STARTED

## Goal

Present relevant advisories with honest freshness and scope.

## Why

This delivers the next bounded part of the local commuter milestone while preserving the data-trust and minimal-design rules.

## Dependencies

[WEB-003](WEB-003.md), [WEB-004](WEB-004.md)

## Scope

Render translated title/description, known effect labels, affected selectors/timeframes, source freshness, safe links and bounded snapshot pagination. Support explicit refresh, loading, empty, error and usable degraded feed states.

## Out of Scope

Unrelated transit feeds, guessed alert severity, notifications and guessed per-train associations.

## Expected Files

app/alerts/page.tsx, components/AlertCard*, alert translation/selector helpers, alert tests.

## Implementation Notes

English translation first, then available fallback; plain text only. Preserve IDs even when titles repeat. No-alert claim requires current usable evidence; retained stale alerts stay visible with historical framing.

## Acceptance Criteria

Four captured advisories can render; unknown numeric effect is neutral; degraded usable feed is not shown offline; links reject unsafe protocols; selector labels do not overstate train relevance.

## Tests Required

Test translation/null handling, duplicate titles/distinct IDs, active-period open bounds, URL sanitization, selector scope, snapshot restart, empty versus unavailable feed and retained stale alerts. Run all checks.

## Manual Verification

Inspect actual alerts and synthetic empty/degraded/error/long-text cases on mobile and desktop; follow safe links and keyboard-test disclosure.

## Design Verification

Inspect rendered mobile and desktop views using [the design checklist](../DESIGN.md). Review hierarchy, spacing, wrapping, color-independent status and applicable loading/empty/error/real-data states. Capture screenshots with the Playwright tooling established in WEB-004 and record them under `docs/reviews/<ticket>/`; state explicitly which states are inapplicable and why. Missing screenshots are an incomplete gate, not a pass. Automated tests alone do not satisfy this gate.

## Definition of Done

All acceptance criteria and required checks actually pass; rendered verification is complete where applicable. Review the diff, record exact results and any limitations here, and update the ticket index, CURRENT_STATE.md and relevant runbook/design/contract docs. One completed-ticket commit with a WEB-008 subject; preserve unrelated work. If blocked, document why and leave IN_PROGRESS rather than making a completion commit.
