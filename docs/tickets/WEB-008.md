## Why

## Implementation decisions

**An empty list claims good news only when the evidence supports it.** With a healthy
alerts feed the screen reads "No active MARC alerts reported"; with a degraded, stale or
unavailable feed it reads "Alert information is unavailable … not evidence that MARC service
is running without disruption". The feed's own `sourceHealth` state decides which, so the
claim can never outrun the evidence.

**A degraded feed is usable, not offline.** Its advisories stay visible with a banner saying
they may be incomplete. A stale feed is framed as last received. Neither is blanked.

**No severity is derived from the effect code.** The feed ranks nothing, so a parking
advisory is not styled like a suspension; inventing a ranking would turn this service's
guess into an apparent operator statement. Only the feed-health banner carries a tone.

**Only documented cause and effect numbers get a label**, from the GTFS-RT tables; anything
else reads "not described". This is the same rule WEB-005 applied to `scheduleRelationship`.

**Text is plain text and links are http(s) only.** `preferredText` treats whitespace-only
translations as absent so a blank string never renders as content, and `safeLink` parses the
URL and rejects any other scheme, so `javascript:` or `data:` content cannot become a live
link.

**Selector scope is reported, never interpreted.** A route or agency entity says what it
says; the screen states once, for the whole list, that this does not identify individual
trains.

## Outcome

Added `lib/presentation/alerts.ts`, `components/AlertCard.tsx` and
`components/AlertsScreen.tsx` with their CSS modules, and replaced the `/alerts`
placeholder. Only `/` remains a placeholder, owned by WEB-009.

Checks actually executed: `npm test` (**9 files, 142 tests**, 0 failures), `npm run lint`
(zero warnings), `npm run typecheck`, `npm run build` and `npx playwright test` (**12 tests,
6 per viewport**).

Rendered verification covered the real retained screen plus four intercepted scenarios.
Measured across every scenario at both viewports: **0 px horizontal overflow, zero non-HTTP
hrefs anywhere, and no page errors**. The empty-state rule is visible directly: a healthy
feed reads "No active MARC alerts reported" while a degraded, stale or unavailable feed
reads "Alert information is unavailable". The stress capture shows `<b>not bold</b>` as
literal characters and produced no link at all for a `javascript:` URL.

One defect was found by looking. The scope caveat repeated verbatim on every card — four
identical sentences on the real screen, which DESIGN.md's duplication check forbids. It is
now stated once for the whole list, pinned by a test.

The real capture turned out to contain **two advisories sharing the same Odenton title**, so
the distinct-identity rule is exercised by real data rather than only by a fixture.

## Limitations

The retained alerts feed is a completed-day snapshot, so the advisories are historical and
the screen correctly says "Reported 1 day ago by the operator". A live feed with a current
timestamp has not been observed here. The loading state is captured only incidentally,
because the local backend answers in well under a second. No external link was actually
followed. Chrome only; not a full accessibility audit.
