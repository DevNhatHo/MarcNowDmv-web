# WEB-006 — Train detail with official and scheduled information

Status: NOT_STARTED

## Goal

Make official status and schedule understandable at a glance.

## Why

This delivers the next bounded part of the local commuter milestone while preserving the data-trust and minimal-design rules.

## Dependencies

[WEB-005](WEB-005.md)

## Scope

Implement opaque-ID detail route with identity, dominant official status, current/last position text, source age, scheduled stops and separate official estimates. Add optional Data status disclosure, cursor-based stop/update loading and back-to-filtered-list navigation.

## Out of Scope

Calculated movement/trend presentation (WEB-007), maps and automatic polling.

## Expected Files

app/trains/[id]/page.tsx, components/TrainStatus*, components/FeedHealth*, components/LastUpdated*, detail tests.

## Implementation Notes

Original-version names require matching catalogs; fall back to IDs. Do not present raw coordinates as near a named place. Top-level nextStop/nextUpdate are pagination cursors. Source diagnostics are secondary.

## Acceptance Criteria

Official and scheduled values remain labeled; stale coordinates read last reported; null/unavailable detail is useful; back link preserves filters; no frontend-derived arrival times.

## Tests Required

Test official/scheduled separation, 404, stale/null position, old schedule version, stop/update cursors, partial page errors, timezone and filter preservation; execute all established checks.

## Manual Verification

Open a real returned train ID and inspect stops/source health. Review loading, unavailable/error and long identity text at mobile/desktop widths.

## Design Verification

Inspect rendered mobile and desktop views using [the design checklist](../DESIGN.md). Review hierarchy, spacing, wrapping, color-independent status and applicable loading/empty/error/real-data states. Capture screenshots when possible; record evidence and inapplicable states. Automated tests alone do not satisfy this gate.

## Definition of Done

All acceptance criteria and required checks actually pass; rendered verification is complete where applicable. Review the diff, record exact results and any limitations here, and update the ticket index, CURRENT_STATE.md and relevant runbook/design/contract docs. One completed-ticket commit with a WEB-006 subject; preserve unrelated work. If blocked, document why and leave IN_PROGRESS rather than making a completion commit.

Map integration is deferred within this ticket, not removed from the roadmap: WEB-MAP-5 will reuse this detail presentation and navigation state. Do not implement map code here.
